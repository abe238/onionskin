# Contract: `onionskin apply` (agent-side anchored edits) and the `done` checks

Schema: `ops.schema.json` (strict, unknown fields rejected). Code: `src/apply.js`, `src/ops/*`, `src/checker.js`, `scripts/checker/check.py`.

## Command

```
onionskin apply <file> --ops ops.json [--dry-run] [--partial] [--batch batch.json] [--holder name]
onionskin reply [<file>] --lease <ticket> [--json '<json>' | --file <path>] [--partial] [--then-poll [--timeout N]]
onionskin setup-checker
```

Runs the engine the browser uses (`vendor/engine-node`, the engine's DOM-free `Engine` class bundled for Node by `scripts/build-engine-node.mjs` from the engine commit in `vendor/engine.lock.json`, locked under its `node` section; bun is only needed to rebuild it). The CLI needs plain `node >= 22`.

## `reply`: apply and done in one call

`onionskin reply` (code: `src/reply.js`) answers a whole batch: `{summary, replies:[{comment, find+replace | text | set | ops | decline, note}], ops?, document_instructions_ignored?}`. It reads the delivered batch from the session (`GET /cli/batch` with holder, batch id and token: the server checks the ticket first, and a refusal ends the command before the reply is planned or the file is read), expands each shorthand into one existing op (`find`+`replace`: `replace_text` for DOCX, `replace_text_in_shape` for PPTX; `text`: `replace_text` with `text` for DOCX, `set_shape_text` for PPTX; `set`: `set_cells`) whose `target` is the comment's anchor id and whose `expect` is that anchor's `locator.text_hash` from the SESSION's batch (never from the agent; a shorthand reply cannot carry either), then calls `applyCommand` with the ops and batch in memory: the same validation, lease ticket, protected checks and atomic or `--partial` write. When the write succeeded it runs the same `done` call with results built from the replies (`done`, or `declined`). In atomic mode any failing op leaves the file untouched, the batch unfinished, the lease kept, exit non-zero, and the JSON names per reply what failed and how to fix it. Output is compact JSON on stdout only; `--then-poll` prints the result line first, then appends the next batch (or a status object, `poll_failed` when the wait itself failed) as a second line. Each comment of a batch also carries `reply_with` (`find_replace_or_text`, `set`, `ops`, `decline_or_ops`), computed from the anchor and free of document text. Reference: the skill's `reference/ops.md`.

## Targets by anchor

Every cell, shape and paragraph op can name its target by the anchor id the batch delivered (`{"anchor_id": "a3"}`), with `expect.text_hash` copied from that anchor's `locator.text_hash`. The batch is read from `--batch batch.json` or, when a session tracks the file, from the server (`GET /cli/batch`). DOCX anchors resolve as before (para_id, body_path + text_hash, text_hash, quote). XLSX `set_cells` / `format_cells`: the locator's `sheet` and `range` are used (give `anchor_id` alone, or `sheet` with `range`, never both); `expect.text_hash` is the hash of the typed text of the whole range, which is what the batch locator carries. PPTX `set_shape_text` / `replace_text_in_shape`: the locator's `slide_id` and `shape_id` (give `anchor_id` alone, or both ids); a slide-level anchor has no shape and is `anchor_not_found`. Addresses and ids are those of the file as the user sent it: an op whose cell changed since fails closed as `expect_mismatch`. Row and column ops (`insert_rows` ...) keep the explicit `{sheet, at}` target and an `expect` of the row's typed text.

What `apply` could not do (`refused`, `skipped_protected`, `anchor_not_found`, `expect_mismatch`) is sent to the session with `POST /cli/apply-report {file, holder, problems:[{op, status, code, reason}]}` (lease holder only), also when nothing was written, and shows up with the activity entry at `done` as flags `apply_not_applied` (warn) and `apply_skipped_protected` (info).

## Semantics

0. **Authorize** (before the file is read or any op runs): an agent Onionskin started may name only its own file (`not_your_file`, see the binding in routes.md); with `--lease` the server must accept the whole ticket for this file (`GET /cli/batch` with the claim), else the command stops with exit 5 and a `write_error` from the server's words, no `results`. `--dry-run` without a ticket still needs none.
1. **Bind** (all ops, against the file as it is before any op runs): the anchor resolves to exactly one unit (DOCX: `para_id`, then `body_path`+`text_hash`, then `text_hash`, then the anchor's quote; never fuzzy), `expect` holds (DOCX/PPTX: `quote` contained in the unit's text, `text_hash` equal; XLSX regions: exact equality of the cells as typed), the unit is not protected (a DOCX paragraph the server classifies as protected, or one the engine marks read-only).
2. **Execute** in order through the engine's own edit methods (`docx.edit`, `xlsx.set|format|sheetOp|bookOp`, `pptx.setText`, `pptx.slides`). XLSX: after an op that inserted or deleted rows or columns on a sheet, later ops on that sheet are refused (`after_structural_edit`): their addresses would mean something else. DOCX table rows and columns (`insert_table_row`, `delete_table_row`, `insert_table_column`, `delete_table_column`, code: `src/ops/docx-table.js`) are not engine edits: bind tries each one on a copy of `word/document.xml` (with the table edits bound before it) and checks `expect` against the row's or column's text; execute runs it on a second copy; save runs them all, in order, on the engine's saved document with the lossless element tree (`src/xml-tree.js`). They address the table as delivered (a table by its order among top-level tables, rows and columns by their delivered index), refuse merged cells they cannot keep whole, and refuse deleting a row or column another op of the file edits. PPTX slide ops (`duplicate_slide`, `delete_slide`, `move_slide`) go through `pptx.slides` by slide id; the slide list the engine returns is checked against what the op must leave, and every later op finds its slide by id. Decks with sections or custom shows, a slide with a chart or other shared part (duplicate) and a slide another part links to (delete) are refused at bind. The package checks report the parts of a deleted slide (its notes, comments and .rels) as `slide_removed` (a warning, which does not recommend Revert), not `part_removed` (an error); `apply` writes a file that lost a slide only when an applied op is `delete_slide`.
3. **Check** the engine's output (`nodeChecks`: part list, relationship targets, element counts) before anything is written. A lost part or relationship, or fewer drawings/links/bookmarks without an op that deletes content, blocks the write (exit 5).
4. **Write**: through the server when a session tracks the file (route `POST /cli/agent-write`: state `working`/`queued`, lease holder only, compare-and-swap, snapshot, atomic write, lease renewed; the ops go with the bytes so that a later XLSX merge of the user's edits can check how the file changed), refused with exit 5 in any other session state (`--dry-run` still works). With no server or no session: standalone, same atomic write plus a snapshot of the replaced bytes in the state dir; the report says so.

Atomic by default: if any op does not apply, nothing is written and the remaining ops are reported `not_applied`. `--partial` writes what applies (it restarts from the original bytes without an op whose execution threw, because the engine cannot roll back).

The DOCX driver has two more ops, `format_paragraph` and `move_paragraph`, for the server's own merge of what the user did during a run (`POST /api/merge`, `src/merge.js`). They bind like every other paragraph op (anchor, `expect`, protected check; a move binds both the paragraph and its new neighbor) and are not in `ops.schema.json`, so an ops file or a `reply` that names them is rejected as an unknown op.

## HTML files (`src/ops/html.js`)

No engine and no package: every op is a splice of the file's source through `src/html.js`, so the bytes outside the edited places stay as they were. Ops: `replace_text` (find and replace inside one element's text, or `text`), `set_text`, `set_attribute`, `remove_attribute`, `insert_html` (`before`, `after`, `first_child`, `last_child`), `replace_element`, `delete_element`, `replace_all_text` (text nodes only: never a script or style body or an attribute value). Targets: `anchor_id`, or `path` or `element_id` from the batch's locator; `expect.text_hash` is the hash of the element's own text, `expect.quote` must occur in its visible text. Script and style elements are frozen (no `set_source`); a mismatch excerpt is the element's visible text, never a script or style body (R7).

Every op binds against the file as delivered; bind builds its edit and refuses one that adds active content (`src/html-active.js`, named by reason codes in `reasons`). Execute refuses an edit that changes a place an earlier op of the file changes (`overlapping_edit`). The run then applies every splice at once, parses the result once and proves it (`proveEdits`: every node outside the edited places equal, each edited place what the ops say), and runs the write check (`src/html-write.js` `checkedHtmlWrite`): the charset declaration on the first non-ASCII write (R10) and the whole-file inventory of active content (R1). The inventory is also positional: every item that is not allowed is bound to its owner (the tag names from the root down to it, its tag and its `id`), and the items after a write must be the ones before in the same order, less some removed, so a move, a swap or a copy of active content between elements is refused like an addition (text edits and allowlisted elements added or removed around it are not). A proof that fails is traced to the op that fails it alone (`proof_failed`; `--partial` writes the rest). A refused write check refuses every op with its code. The package checks do not run for HTML. The work runs in the ops worker (`src/ops-worker.js`); the parser never loads on the CLI's or the server's thread.

The same check runs on every other write of an HTML file, in a worker (`src/html-write-worker.js`): `/cli/agent-write` and `/cli/commit` (session `agentWriteChecked`, then `agentWrite`, which checks the lease, the state and the disk hash again after the await, and writes only bytes whose check it was handed: `unchecked_write` otherwise), a standalone `commit`, and the person's own text edits (from Phase 2a). A whole new version gets decoding, the limits, a parse, the charset rule and the inventory, but no splice proof. A refusal is 422 with `code` and, for `active_content`, `reasons`; the file is untouched.

HTML codes: `spans_markup` (a match or a text across an element's edge: use `replace_element`), `not_addressable` (an element or text the source does not hold exactly: implied, foster-parented, a duplicate attribute to remove, whitespace-only text), `active_content` (reason `The agent tried to add code that runs in a browser, so nothing was written.`), `not_well_formed` (markup that does not read back the same in its place, NUL, a lone surrogate), `overlapping_edit`, `proof_failed`, `charset_needs_head` (a first non-ASCII write with no place to declare UTF-8 within the first 1,024 bytes), `too_large`, `not_utf8`. `replace_all_text` on HTML adds `spans_markup` (matches across an element's edge, not counted) to an `expect_mismatch`.

## Markdown files (`src/ops/markdown.js`)

No engine and no package: the file's text is the document. One op, `replace_source`: `target {from, to}` (UTF-16 code units of the text after any BOM, half-open, as `src/markdown.js` counts them), `expect {sha256, source}` (the batch's base and the exact old text of that range, in full) and `text`. Bind (`src/markdown-file.js` `checkOne`) checks, against the file as delivered: its sha256 is `expect.sha256` (`stale_base`), the range is inside it (`bad_range`), both ends are on character and run boundaries (`src/markdown.js` `offsetAllowed`: never inside an escape, an entity, a soft or hard break, a surrogate pair, a grapheme cluster or a CR LF; `not_a_boundary`), and the text there is `expect.source` exactly (`old_text_differs`). Nothing searches for words. Execute collects the replacements; finish applies all of them at once through `applyReplacements` with the base's offsets (an earlier one never moves a later one), and two that overlap or share a start refuse every op of the run, also with `--partial` (`overlap`). The result must read within `MD_LIMITS` (`too_large`). Everything outside the ranges (a BOM, every line ending, the final newline) is the same bytes.

`apply` sends the ops that applied with the bytes; the session (`agentWrite`) reads the file on disk, checks it is the base, rebuilds the bytes itself from those ops (`rebuild`) and writes only when they equal the bytes sent (`unchecked_write` otherwise), under the same compare-and-swap. `#replace` refuses any other write of a Markdown file: a Send's page bytes (`no_bytes_for_markdown`), a merge, `/cli/commit` and `onionskin commit` (`not_for_markdown`); Revert restores the stored bytes by identity. `reply` expands `text` to one `replace_source` on the anchor's range with its `locator.source` and the batch's base; `find` and `set` are `shorthand_not_for_format`.

## Result codes (per op)

`applied`, `skipped_protected` (reason), `refused` (`code` = the engine's refusal code such as `xlsx-table`, or `unknown_style`, `paragraph_has_objects`, `values_shape`, `after_structural_edit`, ...), `anchor_not_found` (missing or ambiguous), `expect_mismatch` (carries `actual_excerpt`), `not_applied` (nothing was written for this op: atomic mode and another op failed, the package check blocked the write, or the server/standalone write was refused; `would_have` shows what it did in the engine). A `--dry-run` reports what would happen (`applied` = would apply). Document-wide ops (`replace_all_text`, `format_all`) report skipped protected units in `detail.skipped_protected`. An `expect_mismatch` of a document-wide op also carries `found` (what the file really holds) and `protected`; `replace_all_text` adds `partial_words` (matches that touch a letter or digit, such as "he" in "the") and, for XLSX, `in_formulas` (matches in a cell whose typed text is a formula).

## Exit codes

0 all ops applied (or would, with `--dry-run`); 1 error; 2 invalid ops file (report lists the errors); 3 some op did not apply, nothing written; 4 `--partial`: some applied and written, some did not; 5 write refused (server state/lease/conflict, blocked by the package check). The JSON report is on stdout (`onionskin.apply-report/1`).

## `done` checks and the activity entry

Milestone 2 adds the session `stage` value `"local"` and activity entries with `by: "local"` (a change made on this Mac without an agent) and `kind: "review"` (a review the agent ran); they go through the same checks as any `done`. Routes: `/api/quick`, `/api/review`, `/api/suggestion`, `/api/suggest`, `/api/suggest/use` (see `routes.md`).

`flags` are findings: `{code, severity: info|warn|error, ...}`. `checks` says what ran: `{node, deep: {status: ran|skipped, ...}, notice}`; a skipped deeper check is stated in `notice`, never silent, and `deep.code` says why in a stable form (`not_set_up` | `libraries_missing` | `timed_out` | `failed`) so a page never parses the sentence: the browser shows its plain line and "Turn on deeper checks" button only for `not_set_up` and `libraries_missing`, on the newest run, and keeps `notice` for a collapsed Details. While the LibreOffice conversion runs in the background `deep.soffice` is `"pending"` and the notice says so; when it ends the server rewrites that activity entry (`soffice-convert` in `deep.checks`, or in `deep.skipped` with a reason when it could not finish) and adds any `soffice_convert_failed` flag, with `revertRecommended` set only if that run is still the latest and the file is still its version (otherwise the flag is a warning). One background conversion runs at a time for the whole server; others wait in line, first in first out, and the time limit counts from each one's own start. At most 8 wait: one more is recorded in `deep.skipped` as not run. `ONIONSKIN_SOFFICE_SYNC=1` runs it inline in `done` instead. `revertRecommended` is true when any flag has severity `error`.

Deeper check = `scripts/checker/check.py` (lxml, defusedxml rules, python-docx/openpyxl/python-pptx, LibreOffice headless): removed parts, unresolved relationships (target missing, r:id without relationship), per-part decreases of drawing/chart/field/content-control/equation/bookmark/link/comment-reference elements, reopen with the Python library, PDF conversion in a private LibreOffice profile with a hard timeout (skipped when `/Applications/LibreOffice.app` is absent or `ONIONSKIN_NO_SOFFICE=1`; `ONIONSKIN_SOFFICE` overrides the path). It runs when `ONIONSKIN_PYTHON` points at a Python with the libraries, or `<state dir>/venv` exists (`install.sh` runs `onionskin setup-checker` unless given `--no-checker`; the review panel's button does the same through `POST /api/setup-checker`; quick fixes (`onionskin setup-rewriter`, `install.sh --rewriter`) use Apple's built-in model through the ready-made helper in the app folder and download nothing). A checker that crashes or times out yields a `deep_check_failed` warning, not a clean result. Ceiling: `done` waits for the Python checks (timeout `ONIONSKIN_CHECK_TIMEOUT_MS`, default 180 s) but not for the LibreOffice conversion, which runs afterwards in a separate `check.py --soffice-only` process that is ended when the session closes or the server stops (and exits on its own if the server dies).
