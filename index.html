How it works

Three steps, and your agent does the typing in the file.

  1. 1

    Open a file

    In a terminal, type onionskin report.docx. Or tell Claude Code or Codex: open report.docx in Onionskin. The file opens in a browser editor on your computer, with the document on the left and a review panel on the right.

  2. 2

    Mark it up

    Edit text directly. Comment on a selection, cell, range, shape or slide, drop numbered pins, tap a one-tap request like Shorter or Friendlier, or write one overall note.

  3. 3

    Press Send

    The agent changes the real file. The page reloads in place and keeps your position, shows what changed, and lets you revert the last run.

What you can do in the editor

Everything you mark up lands in the review panel, so you can see the full request before you press Send.

  • Edit directly

    Type in the file like any editor.

  • Comment on anything

    A sentence, a cell, a shape, a slide or part of a page.

  • Pins and one overall note

    For a spot on the page, or a change across the whole file.

  • One-tap stamps

    Shorter, Friendlier, Fix grammar, Translate.

  • Review first

    The agent suggests changes as cards. Nothing changes until you accept.

  • History and revert

    See what changed. Undo the last run in one click.

  • Real tracked changes

    Export a Word file with tracked changes, checked in Microsoft Word.

  • HTML pages

    A still view: scripts never run and nothing loads from the internet.

Two ways to start

Start from a terminal, or from inside your agent.

A round from Send to the changed file took about 5 to 13 seconds in our runs.

  • From a terminalType onionskin report.docx. Onionskin starts its own Claude Code agent on your Claude plan.
  • From inside Claude Code or CodexSay open report.docx in Onionskin. The agent you are talking to does the work.
  • Limited on purposeThe background agent changes your file only through Onionskin. In our tests it could not read your other files or reach the network.

Keep working while the agent works

You do not have to wait for a run to finish. In Word, Excel and PowerPoint, keep typing, and your edits are merged with the agent's version when it is done. An HTML page is read only while the agent works; you can still add comments.

  • WordA paragraph-level three-way merge, including formatting and moved paragraphs.
  • Excel and PowerPointA strict merge: your edit is carried over only onto a place the agent did not touch.

Quick fixes, answered on your Mac

Select one sentence in a Word or PowerPoint file and ask for Fix grammar. Apple's built-in on-device model answers on your Mac. Nothing is downloaded, and nothing changes until you tap Use this.

Quick fixes need macOS 26 or later, Apple silicon and Apple Intelligence turned on. Without them, Fix grammar goes to your coding agent.

  • Usually ready by the time you tapThe fix starts when the Quick ask box opens and takes about 0.85 seconds per sentence. On the first fix of a session, or an immediate tap, the card took about 0.3 to 0.4 seconds.
  • Plain commands use no AIReplace in N places and other plain quick commands run on your Mac with no AI at all.

How the pieces fit

Your edits start in a browser tab and finish in the file on disk. The editor and the server run on your computer, and your coding agent edits the file there.

The editor runs on your machine

The editor and its small server run on your computer, on the loopback address only, and the page makes no outside requests. When you press Send, your document goes to the coding agent you already use, Claude Code or Codex. Every batch carries the text of the whole document, not only the part you commented on, because the agent needs it to find the right place.

Your coding agent works the way it already does. Whatever it normally sends to its model provider still applies.

  • No Onionskin cloudOnionskin itself does not upload your files. There is no Onionskin account and no Onionskin cloud.
  • Loopback onlyThe local server listens on loopback, so other machines on your network cannot reach it.
  • Snapshots before changesOnionskin keeps snapshots of your file, including the original, so a revert is one click.
  • Some things never leave the MacQuick fixes and the plain quick commands are answered on your Mac and go nowhere else.

Questions

Is Onionskin released?

Yes. The code is public on GitHub under the MIT license. Install it by pasting the sentence in the Install block into Claude Code or Codex. It is also on npm: run npm install -g onionskin-cli, then onionskin setup. This is a pre-release. To update later, tell your agent "update Onionskin" or run onionskin update.

Can I try it without installing anything?

Yes. The Try-it demo page replays one real recorded agent session in your browser. No install, and no AI runs.

Which coding agents does it work with?

Claude Code and Codex, in two different ways. Type onionskin report.docx in a terminal and Onionskin starts its own background agent, which is Claude Code only and runs on your Claude plan. Or tell Claude Code or Codex: open report.docx in Onionskin, and the agent you are talking to does the work. We exercised both in real agent runs.

Does my file leave my computer?

The editor and its small server run on your computer, and the page makes no outside requests. When you press Send, your document goes to the coding agent you already use, Claude Code or Codex, so whatever that agent normally sends to its model provider still applies. Every batch carries the text of the whole document, not only the part you commented on, because the agent needs it to find the right place. Only quick fixes and the plain quick commands stay entirely on your Mac.

Which file formats does it support?

Word (.docx), Excel (.xlsx), PowerPoint (.pptx) and HTML (.html, .htm). All four run the whole loop. For Office files the file's own formatting is kept because edits go through the same engine that renders it. For HTML, only the bytes the edit touches change.

What happens with HTML files?

You see a still view of the page: scripts never run in it, and nothing loads from the internet. Images and styles in the page's folder are shown. You edit text directly; structure changes, such as a new paragraph, go to the agent as comments. Onionskin never lets an agent add code that runs in a browser, such as scripts, event handlers, frames or forms. Such a change is refused whole. Pages up to 10 MB and 200,000 elements, saved as UTF-8. Chrome is the tested browser.

What does it need, and what is missing?

Claude Code or Codex already installed: Onionskin is for people who already use one of them. macOS only so far, because it is the only platform tested, and Node.js 22 or newer. There is no Windows or Linux version and no real-time collaboration. Quick fixes also need macOS 26 or later, Apple silicon and Apple Intelligence turned on. If something is off, run onionskin doctor to check the install.

How well is it tested?

Over 1,500 unit tests and 380 browser tests pass. On a second Mac with no Onionskin on it, the pasted install sentence, run by a real agent, installed it in 17.5 seconds, onionskin doctor reported OK, and a real round changed the file 4.1 seconds after Send. With the background agent, a real round took about 5 to 13 seconds in our runs on one Mac. Inside a Claude Code session, a warm round took about 2 to 3 seconds.

Can the background agent see my other files?

No. It can change your document only through Onionskin's own commands. In our tests, reading outside its two folders, your home folder, network fetches and writes elsewhere were all refused. It is started without API keys in its environment. It can run read-only commands and read files inside its own work folder and the skill's reference folder.

Can the agent add table rows or slides? What about charts?

Yes to the first two: it can add or delete a table row or column in Word, and copy, delete or move a slide in PowerPoint. Charts are declined with a plain message that says to insert the chart in Word or PowerPoint. A file produced by the new table edits was opened in Microsoft Word, and one with the new slide edits was checked with LibreOffice and a Python reader. It has not been opened in Microsoft PowerPoint.

What is the license?

MIT. Onionskin builds on a fork of the office-engine document engine by p10node (MIT) and on ideas from Peter Yang's human-review (MIT).

How is this different from pasting a document into a chat?

A chat hands you text back, and you copy it into the file yourself. With Onionskin, each note is anchored to the exact spot in the document, your agent edits the real file, and you see every change land in place with a revert button.

Credits

Onionskin stands on two MIT projects.

  • office-engine by p10node (MIT): the document engine that renders and edits .docx, .xlsx and .pptx in the browser; Onionskin builds on a fork of it.
  • human-review by Peter Yang (MIT): the human review loop idea: a command line tool and local server your agent waits on while you mark things up.

Why Onionskin?

Onionskin is a thin, strong paper you can see through. From the 1920s to the 1970s, offices typed carbon copies on it because it was light, cheap to mail and easy to file.

Artists and animators found another use for it. They laid a sheet over a drawing, saw the original through it, and traced the next version on top. A new idea took minutes, and it started from work that already existed.

This tool works the same way. It lays a thin layer over your Word, Excel, PowerPoint or HTML file. You mark what you want on that layer, and your coding agent (Claude Code or Codex) makes the change in the real file. The page updates in place and you keep going.

We built it because we believe the age of AI makes fast edits and fast creation possible, and a lot of today's tools are too heavy for that. A quick change should feel quick. You and your agent should be able to work on the same page, one thin sheet apart.

Sources: CAMEO, Museum of Fine Arts, Boston, American Jewish Historical Society, HIAS archives project, Wikipedia: Onion skinning
