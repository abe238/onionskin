### Added
- Line breaks in an Excel cell: while typing in a cell, Shift+Enter or Alt+Enter starts a new line inside the cell. Tried for real: the saved file had the line breaks 0.6 s after Send. In a narrow column the first line of a tall cell can be clipped until the column is widened.
- What the agent can now do for you, in plain words: add or delete a table row or column in Word; copy, delete or move a slide in PowerPoint; decline a chart in plain words (it says to insert the chart in Word or PowerPoint); understand Excel merged cells (it is told which cells are merged, and a write into a covered cell is refused). A run that only followed the overall note says so ("Changed the file as your note asked") instead of "No change needed", and a copied or deleted slide shows one plain note in the panel.
- Ops for Word table rows and columns and for PowerPoint slides, so the background agent (and any agent) adds a row or a slide without a script: `insert_table_row`, `delete_table_row`, `insert_table_column`, `delete_table_column` by `{table, row}` or `{table, col}` (the numbers of a cell's `body_path`), with the new cells' text in `cells` and the neighbor's formatting; `duplicate_slide` (the way to add a slide: the copy's text is set in the same op), `delete_slide` and `move_slide` by `slide_id`. Each has `expect` like every op. What they cannot do without damage is refused with a code: merged cells a row or column would split, the last row, column or slide, protected content or half a comment in what a delete removes, a slide with a chart or another shared part (duplicate), a slide another slide links to (delete), decks with sections or custom shows. Nothing creates or changes a chart. A deleted slide's parts are reported as `slide_removed`, a warning instead of the lost-part error, so a requested delete does not recommend Revert (a `commit` that drops a slide now gets the same warning instead of the error). Real background-agent runs of the new `scripts/real-run` scenarios `docx-table-row` and `pptx-duplicate-slide` applied them, and LibreOffice converts the results; they have not been opened in Word or PowerPoint yet.
- The background agent: Onionskin starts, restricts, supervises and stops a headless Claude Code agent per document (`src/agent-runner.js`, `src/agent-detect.js`, `src/agent-prompt.js`), so a person who never opened an agent still gets their Send answered. It starts when a file is opened from a person's terminal, when a Send finds nobody listening (at once for such a file, after a 20 s grace for any other, so an agent of your own between two polls keeps the batch), or from the page (`POST /api/agent {action: start|stop|use|show|terminal}`, the editing tab only, a 1 KB body of fixed values). Claude Code only in this build, model sonnet by default. Least privilege, proven on Claude Code 2.1.323 with one real probe of the rule forms and real full rounds on the prompt-injection fixture (open, Send through the real server, reply by file, the change shown, Close; state folder under the home folder like `~/.onionskin`): `--restricted --tools Bash,Read,Write`, it changes the document only through Onionskin's own commands (`onionskin poll|reply|status` are the shell commands granted by name), it may write only inside its own work folder (`Edit(//<folder>/**)`), it may read files inside its own work folder and the skill's reference folder (`--add-dir`) and run read-only commands, and a probe with canary files showed that reading outside those two folders, reading the home folder, network fetches and writes elsewhere were all refused, `--permission-mode dontAsk --permission-prompts none`, no settings files, MCP servers or slash commands of the person's own setup, and an environment built from nothing (no `ANTHROPIC_API_KEY` or any other key, so it always uses the person's subscription). The agent answers by writing the reply JSON to a new file per batch and running `onionskin reply --lease <ticket> --then-poll --file <that file>`; `reply` refuses `--json`, stdin and any file but `<that folder>/reply-<batch id>.json` for the background holder and for its Terminal form (`onionskin-term-`, bound to its own file the same way), and its JSON errors there never quote the input. Such an agent cannot open the file, so every edit batch it receives, complete or compact, also carries the document's outline as quoted evidence (`untrusted_document_evidence.outline`: each paragraph, text shape or cell as it is at that delivery, with the `target` and `expect` an op copies; as much as fits one shell output inline; when that is not all of it, the complete outline, up to 2,000 units, in a file of one unit per line in the agent's own outline folder, which it reads with the Read tool and which is the only part of its work folder it may read; `outline_more` counts what it cannot see), so a note with no comment or selection, such as "change the title", is done; every other holder's batch is unchanged. Each agent is its own process group with a record of its pid and start time; it is signaled only while `ps` still shows that start time, and a server that starts stops the groups a crashed one left. It stops on Close session, server stop, 20 minutes without a tab, or when an agent of your own polls the file (that agent supersedes it, and a background poll never takes a file back). A crash hands the batch back at once (the page unlocks, a run that wrote keeps Revert) and restarts with backoff 2 to 32 s, resuming the conversation, at most 5 starts per document an hour; signed out, a usage limit or a refused command never restarts by itself. At most 3 agents run at once. Its own polls do not keep the server alive, and its `poll` never starts or restarts a server (a stopped server ends it with `closed`); a poll that outlives its agent process is answered `closed`, so a Send never waits on nobody. "Open in Terminal" opens the same conversation in Terminal with the same limits (tried in a real Terminal: the file changed 17.7 s after Send). Its stream is kept as a private transcript (0600) in the state folder and removed, with Claude Code's own copy, when the session is closed (also after a server restart). The holder prefix `onionskin-bg-` is reserved (400 `reserved_holder` for any other file). Tests never start an agent unless they opt in (`ONIONSKIN_AGENT_PATH`); `ONIONSKIN_AGENT_CLI=none` turns it off. `scripts/real-run/bg-real.mjs` is the opt-in real test (`ONIONSKIN_REAL_AGENT=1`; `--fake <dir>` rehearses it for free). On the page: when nobody is listening, the banner has a Start the agent button in place of the `onionskin poll` command line; an agent that is starting, stopped (not installed, not signed in, plan limit reached, crashed, kept stopping, refused a command) or open in Terminal each shows a plain banner with its buttons (Try again, Restart the agent, Send again, Show what happened, Open Terminal to sign in, which opens a Terminal running `claude auth login`; an outdated Claude Code says to update it; a fourth document's agent says another document's agent is busy); a Background agent block in the review panel has a Show the agent switch with a live list of what it is doing (fixed plain lines built from the agent's stream by `src/agent-events.js`, never document text) and Open in Terminal; `agent` settings (`cli`, `model`, `show`) in `settings.json`. Claude Code is the only background agent in this build.

### Changed
- The engine is office-engine v0.13.2 plus our own additions. The owner's typing fix was merged upstream and is part of v0.13.2 (https://github.com/p10node/office-engine/pull/2).
- A Send that carried only your own edits now ends with the summary "Your edits are saved. Nothing else needed changing." It said "No change needed", which read as if your edits were not kept.
- Install is one sentence: paste "Install Onionskin from https://github.com/abe238/onionskin" into Claude Code or Codex. The README has a marked block for the agent doing the install, `AGENTS.md` (and a `CLAUDE.md` pointer to it) carries the same steps, and `scripts/get.sh` ends by saying what was installed and the one sentence to tell the person. `ONIONSKIN_BASE_URL` changes the folder `get.sh` downloads from.
- The README is a short public page; install options, the command list, the feature tour, limits and the full install and troubleshooting notes moved to `docs/DEVELOPERS.md` and `docs/GUIDE.md`, and `INSTALL.md` is a short page. The skill's description now also matches phrases such as "open report.docx in Onionskin".
- Quick fixes feel faster: when the Quick ask box opens on one sentence and quick fixes are on, the page asks for the Fix grammar suggestion right away and holds it, so the card is there when you tap Fix grammar. Nothing shows before the tap. The answer is the same request a tap makes (Apple's model on this Mac only, the same checks), held only for that exact sentence, place and file version, used once, and dropped when the box closes; the page's asks run one at a time and a closed box's waiting ask is dropped, so a tap in the same page never meets "busy" because of it (a head start in another tab or file still can, for about a second: the model takes one sentence at a time for the whole server). With quick fixes off or not available nothing is asked. Measured on the real model in a real browser: Apple's model takes about 0.85 s per sentence, so a tap about 1 s after the box opens finds the card ready (in milliseconds; 3 ms in one run on one Mac), and the first fix of a session or an immediate tap waits about 0.3 to 0.4 s. An earlier build's measurement (one run of 6 sentences each, medians of taps 2 to 6) read 0.08 s for a tap 1 s after the box opened and 1.02 s for a tap as soon as the test could click, against 1.35 s and 1.59 s before the head start; those figures are superseded by the current ones above. `scripts/rewriter-eval/grammar/latency.mjs` times the helper itself (cold, after a warm-up, and 30 sentences of the benchmark set); the helper is unchanged: answering on a prewarmed session was about 200 ms faster but changed 2 answers of 30, and the other prewarm variants kept the answers but were no faster or slower.
- Quick fixes use Apple's built-in model only, by the owner's decision after a benchmark on 160 unseen sentences (Apple with a re-tuned prompt: a good fix shown for 72 of 96 errors with today's checks, 70 when the decision was made; 4 of 64 correct sentences wrongly changed, 3 of them shown; the other helper tried, an IBM model that had to be downloaded, 68 of 96 and 11 of 64). On a Mac where Apple's model cannot answer, Fix grammar goes to the agent, and `onionskin doctor` and the bootstrap's `suggest.unavailable` field say why: "Quick fixes need macOS 26 or later.", "This Mac cannot run Apple's on-device writing model.", "Turn on Apple Intelligence in System Settings to get quick spelling and grammar fixes.", "Apple's writing model is still getting ready. - Quick fixes never change quoted text: the server withholds a suggestion that changes words inside quotation marks (straight or curly, double, or single when they are clearly quotes and not apostrophes), or drops the marks, with the line "No suggestion here: the change is inside quoted text." ### Fixed
- The Ask and Comment chip no longer sits on the line of text above the selection: it goes beside the end of the selected words, else below them, else above, whichever covers the least text, and stays inside the page.
- `onionskin <command> --help` (and `-h`) prints that command's own usage for every command, and runs nothing. `setup-rewriter --help` used to answer "unknown option --help".
- A finished run whose comment you deleted lists that line as "A comment you deleted" (it said "A deleted comment"), with the status and the agent's note beside it.
- The line "Select one whole sentence to get a suggestion first." no longer shows for words in a table cell (Word or PowerPoint) or a protected shape, where no selection can ever get a suggestion. The tap still goes to the agent.
- The Ask and Comment chip now shows when you select again the sentence you just sent from Quick ask (it could stay away until you selected something else first, for example right after Take back).
- Quick ask: a plain click in the document, outside the box and outside the words it asks about, closes the box and keeps any typed words as an unsent comment. The caret stays where you clicked and nothing scrolls. A click on the asked words, in the box, on the panel or on a toolbar control leaves it open.
- Selecting a whole paragraph by triple-click, or by dragging past its end, now shows the Ask and Comment chip on the last paragraph of a page (the browser ended the selection on the page's footer and the editor reported no selection).
- Comment and Pin modes: a double or triple click makes one comment or pin, not one per click.
- Quick ask: Esc closes the open card, then the box, with the focus anywhere in the document (it only worked inside the box); it leaves your place where it is, keeps any typed words as an unsent comment, and does nothing while a dialog or text composition is using Esc. Selecting other words while the box is open closes it and keeps what was typed as an unsent comment, the same as when its words scroll out of view. A page the editor redraws for a moment no longer closes the box.
- After Use this, the caret is back in the rewritten sentence's paragraph, so typing goes there and the formatting bar shows that paragraph's style. Before, when the file's reload arrived in the moment between the box closing and the focus coming back, the caret stayed where the reloaded editor puts its own, at the top of the file: the bar showed the title's style and typed text went into the title. ### Security pass fixes
- The browser cookie alone no longer opens anything: a launch token handed to the page once (kept in memory and the page's own sessionStorage) is required on every API request, so another local port that is sent the cookie cannot use it. A new tab needs `onionskin open` again and says so.
- New `onionskin commit <file> --from <copy> --lease <ticket>` for edits made with python-docx, openpyxl, python-pptx or any other tool; the skill now says to edit a copy and commit it. `done` flags (error, Revert offered) a file that changed during the turn by any other path.
- Every writer (Send, agent write, commit, revert, standalone apply) holds an advisory lock from the hash comparison through the rename and re-hashes the file right before it; a raced write keeps the newer bytes in a snapshot and returns the conflict.
- Agent writes and apply reports always need holder, batch id and token (`missing_lease`); `apply`, `commit` and `done` need `--lease` while a batch is delivered (no per-file fallback); `status <file> --ticket` re-reads it for the agent that polled. A ticket, batch or saved delivery makes `apply` and `commit` fail closed when the session is gone, closed or revoked; writing without a session needs `--standalone` and is refused beside a live session.

### Fixed (milestone review)

- `done` cannot strand queued comments, and it cannot be completed by an agent whose lease expired (`stale_batch`); `poll` now prints a `lease` that `apply` and `done` send back.
- Take back after the agent wrote keeps Revert working; comments added while the agent works are anchored where they were placed; the overall note is sent once.
- Leaving the page with unsent typed edits asks first; Close offers "Download my edits".
- A repeated paragraph or word is no longer matched to the wrong place after an agent edit; protected paragraphs come from the engine's own classifier.
- Two servers starting at once can no longer unlink each other's socket.
- Tests run from a fresh clone: repo-relative fixtures, `node scripts/fetch-fixtures.mjs` for the real Office files.
